# Internationalization Guideline

How copy works across MoneyTrack. Applies to every string a user can read —
including `aria-label`, `title`, `tooltip`, and `sr-only` text.

## Never write a user-readable string in a component

Copy lives in `messages/<locale>.json`. A literal in a component is a string
that exists in exactly one language, and nothing will ever tell you it is
missing from the other two.

```tsx
const t = useTranslations("auth.login");
<Button>{t("submit")}</Button>
```

`useTranslations` works in both Server and Client Components. On the server you
can also use `getTranslations`, which is async and required in an `async`
component.

## `en-US` is the reference; all three change together

`messages/en-US.json` is what TypeScript checks `t("…")` keys against — the
augmentation lives in `global.d.ts`. `pt-BR.json` and `de-DE.json` are checked
only by `src/i18n/messages.spec.ts`, which asserts identical key sets,
identical `{placeholders}`, and no empty strings.

So: **add a key to all three files in the same commit.** The compiler will not
catch a missing German string. The test will.

The three locales are `en-US`, `pt-BR`, `de-DE`, declared in
`src/i18n/routing.ts`. Nothing else hard-codes that list.

## Interpolate numbers, never write them into copy

```json
"tooLong": "Name must be at most {max} characters."
```

```ts
t("name.tooLong", { max: MAX_NAME_LENGTH })
```

A `60` written into three catalogs is three places to forget when the bound
changes.

## Navigate with `@/i18n/navigation`

`Link`, `redirect`, `useRouter`, `usePathname`, and `getPathname` come from
`@/i18n/navigation`, not from `next/link` or `next/navigation`. Call sites keep
their English path — `href="/dashboard"` — and the active locale is added
automatically. See `.claude/rules/navigation-loading.md`.

The exception is a URL handed to a third party. `callbackURL` and
`errorCallbackURL` in `GoogleButton` are sent to Google and to better-auth, so
they are built by hand from `useLocale()`. Those two are the only places in the
app where a locale is written into a path manually.

## Validation and error messages

zod schemas are factories taking a translator — see
`.claude/rules/validation.md`.

better-auth error **codes** are the contract. The server throws an English
message alongside the code; the UI renders `authErrorMessage(t, error.code)`
and never `error.message`.

## Testing

- Schema and error-map specs assert **keys**, using a key-echoing stub. Copy
  changes must not break them.
- Component specs render through `renderWithIntl` from `@/test-utils/intl`,
  which supplies the real English catalog — so the English copy itself stays
  under test.
- e2e specs run in `en-US` via the `path()` helper in `e2e/helpers.ts`.
  `e2e/locale.spec.ts` covers negotiation and the other two locales.
